Now that you know what binary search is, let's explore the built-in C++ functions that use it.

The lower bound function works by finding the first value that is not higher than the target. As we know the list is already sorted, so it uses binary search, to find the highest number accepting the condition. The "first value" means that if the list is {10, 20, 30, 30, 40, 50} and the right number is 30, it will return the index of the first 30 and not any of the others.

This means that the function returns an iterator and not a value.

Below we will explore some of its capabalities and the syntax.

Code

This is the lower bound syntax.

vector v = {10, 30, 31, 40}
int answer = *lower_bound(v.begin(), v.end(), 30);

Honestly, I recommend learning the basics of C++ if you haven't already, but I will still do my best to explain it to you as beginner-friendly way as possible

First of all, a vector. The function needs a vector to work properly. A vector is basically an array on steroids. It does not need a fixed size. Instead you can add or remove elements to and from it quite easily. Many C++ functions need a vector to work.

Lots of those functions though, do not return the straightforward answer. That's actually quite smart as we will see. Instead, they return an iterator. We do not typically use them as they are, and to access them, we use the dereference operator. It's job is to find the value that the iterator is pointing to. Imagine the function is a person, who solves equations. Instead of telling you the answer, he draws an arrow towards the answer. That is the iterator. With the arrow alone, you cannot make sense, but with the whole picture you see where the arrow is pointing and understand.

Now, that we understand the iterator logic, let's look once more at the second line.

We have an asterisk (*) before the function. That is the dereference operator. Then we have the function itself. It has 3 arguements. The first one is the beginning of the search range. Then the end of it. Then the target.

That's it actually...

Oh, but what happens if it finds nothing? It returns v.end. Obviously, v is the name of the vector so if it was called Collywobbles, it would return Collywobbles.end. Don't call it Collywobbles though. So you should check using if ("thefunctionresult" != v.end)

Next, we'll take a look at the upper bound function

The upper bound is extremely similar to the lower bound..

The condition is different. In lower bound, the target can be equal to the output, while the upper bound cannot.

The main difference is the first value that is greater than the target.

For example {1, 2, 3, 4, 5} upper_bound 3 is going to be 4

Code

This is the upper bound syntax.

vector v = {10, 30, 31, 40}
int answer = *upper_bound(v.begin(), v.end(), 30);

As you saw, it the same idea, and syntax, but the result will be different (31).
